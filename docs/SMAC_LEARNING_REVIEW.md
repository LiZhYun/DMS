This review separates verified implementation differences from explanations that still need experiments. It was prepared on 2026-10-25, after the 20-environment, history-16, masked IPPO run completed 1M transitions with zero wins in 8,678 training battles and zero wins in its final ten diagnostic games. Its final mean return was 8.1568; nine games reached the 150-step limit. These observations do not identify a cause or settle the paper's 10M-step claims. The ongoing 3M sequential-update pair should remain intact. Sequential-update mathematics is outside this review.

The local `reference/` directory contains the archived DMS implementation and official SMAC, not an independent official MAPPO/HAPPO checkout. The legacy launcher imports `configs/config_sc2.py`, whose values differ from generic `config.py`. The official upstream files linked below were inspected read-only; their current defaults are useful comparisons, not proof of the exact historical experiment or universally optimal settings.

| Setting | Manuscript / archived SMAC implementation | Current 20-environment development control |

| Training budget | Paper: 10M transitions, six training seeds | 1M completed; separate 3M trials ongoing |
| PPO collection | 20 environments × 160 steps; one minibatch, five epochs | Same 3,200-transition collection and five epochs; dead-agent rows removed per agent |

Manuscript evidence is in [the supplied TeX](../paper/source/Coordination%20as%20Inference%20in%20MARL.tex), lines 782–810 and 903–913. Archived evidence is in [the actual SMAC parser](../reference/DMS/configs/config_sc2.py), lines 249–310; [the launcher](../reference/DMS/scripts/train_smac.sh), line 12; and [the trainer](../reference/DMS/algorithms/happo_trainer.py), lines 163–199 and 279–338. Parser action types matter: some legacy command-line flags disable features despite their names. The launcher also sets gamma 0.95 and 20M steps, conflicting with some manuscript settings; it is not an exact paper specification.

Official MAPPO's [3s5z script](https://github.com/marlbenchmark/on-policy/blob/main/onpolicy/scripts/train_smac_scripts/train_smac_3s5z.sh) uses eight environments × 400 steps, five epochs, one minibatch, 10M transitions and 32 evaluation games. Its collection count is therefore also 3,200; increasing from four to twenty environments already addressed batch count, while trajectory layout still differs. The [official parser](https://github.com/marlbenchmark/on-policy/blob/main/onpolicy/config.py) specifies 5e-4 actor/critic rates, norm cap 10, entropy 0.01, Huber/value normalization and recurrent policies. These defaults assume policy sharing and centralized values unless explicitly changed. The [official HARL HAPPO defaults](https://github.com/PKU-MARL/HARL/blob/main/harl/configs/algos_cfgs/happo.yaml) also use separate actor/critic rates 5e-4, cap 10 and Huber/value normalization, but are a newer general configuration, not a recovered 3s5z paper run. None of this licenses adding global information to the present actors or critics.

**First priority: determine whether the joint gradient cap actually matters.** Current [training code](../src/dms/train.py), lines 199–207 and 458–481, combines policy, entropy and scaled value losses, then clips all of one agent's parameters together. The [official MAPPO trainer](https://github.com/marlbenchmark/on-policy/blob/main/onpolicy/algorithms/r_mappo/r_mappo.py) clips actor and critic independently. With disjoint parameter sets, current clipping scales both gradients by `min(1, cap / sqrt(actor_norm² + critic_norm²))`; a large critic gradient can therefore alter the actor's gradient scale. This is a verified coupling, not evidence that it explains zero wins. Adam's adaptive moments mean changing the cap from 0.5 to 10 does not multiply parameter updates by twenty, and a constant gradient rescaling can largely cancel in Adam.

The smallest next step is a counterfactual optimizer diagnostic on one fresh 3,200-transition rollout from the immutable completed IPPO checkpoint: clone weights, optimizer moments, RNG and cached data; compare cap 0.5 with cap 10; record pre-clipping actor/critic/global norms, clipping fractions and actual policy changes. This is an ephemeral update experiment, not a zero-update evaluator or a return-improvement test. Only if the cap binds and materially changes the update would a fresh seed-101 IPPO learning trial changing this one scalar be justified. Keep its source, budget, local inputs and evaluation schedule matched to the control. Current `max_grad_norm` also clips the intention model at [train.py](../src/dms/train.py), line 532, so applying this change to DMS would additionally change auxiliary learning and would not isolate PPO.

**Second priority: quantify the timeout objective difference.** Current [SMAC decoding](../src/dms/smac_env.py), lines 248–259, marks a native episode-limit event as truncation. [GAE](../src/dms/returns.py), lines 53–64, correctly implements that declared convention: it retains `gamma * V(final observation)` and stops recursion across reset. The archived [runner](../reference/DMS/runners/separated/smac_runner.py), lines 152–159, clears its episode masks; with `use_proper_time_limits=False`, the [legacy buffer](../reference/DMS/utils/separated_buffer.py), lines 209–221, suppresses that bootstrap. Thus these implementations optimize different boundary targets. Neither convention can be declared universally correct without specifying whether the 150-step cutoff is part of the task or merely a sampling limit.

Use the same frozen rollout to count timeouts and true terminations and compare current returns with a terminal-at-timeout counterfactual. Report final bootstrap values and per-agent GAE/return differences, especially their distance from the cutoff. For a time-limited battle objective, large positive continuation values at losing cutoffs could matter; this is a hypothesis, not a conclusion from long games. A later learning comparison should expose a named SMAC-only semantics option and preserve native timeout flags, reset behavior, rewards, local observations and auxiliary inference. Do not silently change the shared GAE implementation or MuJoCo semantics. This is the second bounded hypothesis; do not combine it with the cap experiment.

Other differences should remain documented rather than becoming a tuning sweep. Reward scale 20, positive damage rewards, win bonus 200, death value 10, difficulty 7 and step multiplier 8 agree with the archived environment's defaults. The current actor receives native local observations, visible ally previous actions, its own previous action and public identity; no missing centralized state is indicated. The archived `add_center_xy` option affects state construction and should not be copied into local inputs without a visibility audit. The official [recurrent layer](https://github.com/marlbenchmark/on-policy/blob/main/onpolicy/algorithms/utils/rnn.py) carries hidden state and normalizes it; the current [history encoder](../src/dms/recurrent.py), lines 94–124, starts a fresh GRU for each finite window. Increasing memory length or replacing normalization would be another architectural hypothesis, not a repair established by the present results. Likewise, cumulative observation-statistic changes can alter a fixed policy between rollouts; measuring that drift is preferable to assuming it is harmful.

The two proposed diagnostics preserve decentralized local actors/critics and the intention-inference contract. Neither introduces new held-out seeds or claims a successful reproduction. Retain all zero-win checkpoints and await the registered longer-budget evidence before selecting a learning variant.

Follow-up evidence, 2026-10-26: the 3M sequential pair completed with zero final evaluation wins for both algorithms. Counterfactual diagnostic **21199511** passed, but its gradient cap did not bind: all 40 raw norms were below 0.5 (maximum 0.3442), and caps 0.5 and 10 produced identical final states. No clipping sweep was launched. The rollout contained 19 timeouts; active timeout bootstrap averaged 1.2751 and removing it changed 2.28% of raw advantage signs. The explicit SMAC-only deadline option passed numeric, regression and native checks in **21208924**; a separate 3M comparison is running. See [the diagnostic ledger](../reports/development-smac-gradient-clipping.json), [validation](../reports/smac-time-limit-validation.json), and [current status](STATUS.md). These observations apply to one late checkpoint and do not establish a return benefit from changing the deadline objective.
