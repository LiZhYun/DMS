# Implementation decisions

The user authorized a readable redesign that preserves the method's core and must eventually exceed the paper's reported performance. This file describes the implemented design rather than implying that every historical detail has been reproduced. Manuscript facts and ambiguities remain in [PAPER_CONTRACT.md](PAPER_CONTRACT.md).

| Area | Current decision and reason |
| --- | --- |
| Learning base | Independent PPO remains the default, with separate actors, critics, and intention models per observer. Optional `update_mode=sequential` adds the paper's random agent order and detached predecessor likelihood correction with frozen features by default. Its coordinated training signal is explicit in the manifest. Match the update mode in no-intention comparisons; see [the update guide](SEQUENTIAL_POLICY_UPDATE.md). |
| Execution intention | Use the prior's deterministic mean, inferred only from recorded local behavior. Future-informed posterior samples are training-only. Deterministic actor features avoid treating newly sampled latent noise as a policy change in PPO ratios. |
| History | A configurable rolling window, initially 32 actions, replaces an entire-episode GRU history. It bounds memory and makes the input sequence inspectable. The synthetic smoke uses eight steps solely to keep the check small. |
| Posterior and prior | Share the same GRU, LayerNorm, and Gaussian head; the posterior additionally sees a completed future suffix from the same episode. No future action enters the acting policy. |
| Loss | Minimize reconstruction negative log likelihood plus weighted analytic `KL(q || p)`. The Gaussian likelihood sign and KL log-ratio typo are corrected. NLL averages valid time/peer targets, whereas KL averages eligible peer sequences: the effective sequence KL weight is `kl_beta × valid_targets / eligible_sequences`, or `kl_beta × H` for fully observed H-step suffixes. This is a time-normalized beta objective, not the canonical sequence ELBO at beta=1. Missing/padded targets are excluded; posterior samples are averaged. See [the diagnosis](INTENTION_DIAGNOSIS.md). |
| Decoder | Autoregressive continuous action deltas accumulate from the most recent visible past action. The likelihood target is the actual observed future action; a continuous target is valid only when its actual predecessor and endpoint were observed. Discrete decoding predicts categorical logits, not arithmetic differences between action IDs. The decoder never consumes its target future actions. |
| Decoder dependence ablation | `decoder_history=true` retains a direct encoded-history input to the decoder, matching the initial implementation. `false` initializes the decoder from the latent alone while retaining its last-action anchor and peer identity. This controlled variant tests whether the direct history path makes the latent redundant. The first HalfCheetah diagnostic showed little forecast degradation when latents were shuffled; it motivates the experiment but does not establish that the new variant is better. |
| Coordination | `soft`, `causal`, and `all` are separate variants. Soft attention uses own inferred intention only as its query, excludes self from the peer outputs, and pools the weighted peer intentions. Causal selection computes `KL(full policy || policy without peer)` and compares with the threshold. Causal/all retain separate masked peer slots; an empty peer set produces zero context. |
| Long/short filter | Compare `KL(long-window prior || short-window prior)` with threshold 1e4, initially using four recent steps. Recompute features with rejected inputs masked. This explicitly resolves the manuscript's unspecified KL direction. |
| Stable PPO input | Cache normalized observations, prior features, and hard selection gates during collection. With `intention_rl_lr=0` (default), PPO minibatches reuse those values and RL gradients do not update the intention model. Positive values re-encode the same locally observed past for every minibatch, letting actor/value/entropy losses train the prior. Filtering masks and selection gates stay fixed for the rollout surrogate. Auxiliary updates still follow PPO. This option currently supports soft/all coordination, uses separate Adam moments for RL and ELBO, and does not implement the paper's soft target update. See [joint training](JOINT_INTENTION_TRAINING.md). |
| Warmup and schedule | The actor ignores intentions for the first 100 completed environment episodes in benchmark configs. The auxiliary model can train during warmup. Two auxiliary updates follow each PPO update by default. There is no Polyak averaging in this implementation; do not claim the paper's stabilization recipe was copied exactly. |
| Causal initialization | The causal variant initially exposes all visible peers for another `causal_warmup_episodes=100` episodes, allowing its actor to learn sensitivity before applying the hard KL gate. This is an explicit redesign to avoid an initially empty gate preventing any intention input from learning. Set this value to zero to apply the manuscript threshold immediately after intention warmup. |
| Initial continuous exploration | `initial_log_std=-0.5` preserves the initial Gaussian standard deviation `exp(-0.5)`. The optional setting changes only initial continuous action noise, is saved in the configuration, and is replaced by learned values when a checkpoint loads. Development `-1` is near the original code's approximately 0.366 initial standard deviation. It is not a learned-performance claim. Discrete policies are unaffected. |
| Ant contact forces | `ant_contact_forces=native` preserves the compatibility adapter. Opt-in `computed` runs `mj_rnePostConstraint` before the native Ant reward calculation and after reset, repairing the measured missing force arrays on this stack. It changes existing local force observations and contact penalties, uses a separate adaptation track, and cannot pass the reference release gate. See [the force audit](ANT_CONTACT_FORCES.md). |
| Normalization | Running observation statistics and PopArt-style value rescaling improve optimizer conditioning. These are implementation choices, saved with the checkpoint. |
| Optional local policy memory | `policy_history_length=0` preserves the initial feedforward policy. Positive lengths use separate actor/critic GRUs over bounded windows of the observer's existing local observations. PPO caches normalized input windows and recomputes learned encodings; it never reuses a hidden state generated by old parameters. This differs from the original stateful recurrent policy. See [the memory guide](LOCAL_POLICY_MEMORY.md). |
| SMAC inactive samples | `mask_inactive_agents=false` preserves the initial trainer. The opt-in setting removes dead-unit rows from actor/critic losses, entropy/KL, advantage statistics, and observation/PopArt moments. Team GAE continues across individual deaths. This is a joint masking and normalization change; the dead-critic bootstrap tradeoff is documented in [the training diagnosis](SMAC_TRAINING_DIAGNOSIS.md). |
| Global reconstruction | No optional global-state reconstruction objective. No centralized state or other agents' private observations enters an actor, critic, or intention target. |
| Episode boundaries | True termination suppresses bootstrap; time-limit truncation retains the final observation for bootstrap and cuts the advantage trace. Resets clear recorded history. One SMAC unit dying does not terminate its team's episode. |
| Checkpoint meaning | Checkpoints preserve model/optimizer/RNG data for inspection and evaluation. Environment state is not restored, so they are not advertised as exact trajectory-resume checkpoints. |
| Environment stepping | Optional `parallel_env_steps=true` steps distinct simulators concurrently, then waits for the complete ordered batch. Policy inference, random action sampling, history updates, and episode resets remain on the main thread. All submitted steps finish before a failure is raised or environments close. Serial stepping remains the default. |
| SMAC process lifetime | Before a new episode, recreate a game whose native clock has reached 500,000 loops, below the SC2 lifetime limit. Completed rewards/terminal observations are retained; restart seeds follow the recorded deterministic schedule. Missing battle results still raise an infrastructure error. See [the environment audit](SMAC_ENVIRONMENT.md). |
| Run failure records | Training/evaluation failures after manifest creation mark the run failed, record the exception, last completed update budget, and environment runtime diagnostics, then propagate the error. Scheduler termination still requires inspecting the job accounting and logs. |

## Local information is an explicit interface

`EnvStep` contains observations, shared rewards, termination/truncation flags, legal-action masks, observed previous actions, and an observer-by-peer visibility matrix. Intention history is ordered `[environment, history, observer, peer, action_feature]`. The component mask distinguishes real action coordinates from padding or unobserved actuator components; it is not the same as a discrete legal-action mask.

SMAC enables the native `obs_last_action=True` option. Peer commands are extracted from each observer's own ally feature block using its native visibility bit; the adapter never broadcasts SMAC's global `last_action` array. An agent's own previous command and public identity are added to its actor observation so IPPO receives the same local information. Self history is visible only while alive. The native `continuing_episode=True` flag makes SMAC expose time limits separately from battle endings.

Modern MaMuJoCo explicitly augments local observations with a previous-control sensor. It reveals only actuator components belonging to joints in the observer's configured observation graph. Merely seeing a joint angle or velocity does not reveal its torque; this is a declared sensor assumption. Every comparison receives the same augmentation. The original paper does not specify the corresponding sensing API.

## Environment and hyperparameter differences

The modern MuJoCo adapter uses Gymnasium Robotics MaMuJoCo with v5 tasks. A separate historical compatibility adapter preserves the original graph and v2 assets on Gym 0.23 / MuJoCo 2.1, including the supplemental Swimmer task. Physics, reward defaults, health termination, reset distributions, and observation features must be audited before scores can be compared directly. Neither track establishes parity with the paper's unrecorded binary stack by itself.

The initial benchmark configs use the paper's hidden width 64, five PPO epochs, 10-million-transition budget, discount .99, clipping .2, and intention learning rate .001. Initial actor/critic rates are .0003/.001, latent width eight, GAE lambda .95, and 32-step history; these are redesign starting points, not values recovered from the manuscript. Continuous runs use entropy coefficient zero; discrete SMAC starts at .01. The historical rates remain recorded in `paper_targets.json`.

MuJoCo starts with four environments and a 1,000-step rollout. SMAC starts with four environments and a 160-step rollout, compared with the paper's 20 environments. This reduces initial resource requirements but changes optimization batches and must be reported. Both configs divide exactly into 10,000,000 transitions. Keep transition budgets fixed while measuring the effect of rollout parallelism.

The provided DMS configs initially select soft attention because it is differentiable. They are development candidates. The paper's causal selection remains a required experiment, including checks that its selected-peer rate is nonzero where coordination is useful. Set `filter_history=false` for the no-history-filter ablation. A run whose latent or gate never affects behavior does not validate intention-based coordination.

## Changes still need evidence

Unit tests establish mathematical and information-flow properties, not performance. Required empirical checks include future-action prediction against persistence, latent variation, causal-score/selection diagnostics, no-intention and no-filter ablations, matched sensors, and fixed-budget multi-seed results. Claims must identify the environment track, visibility assumptions, optimizer, coordination variant, and completed evaluation protocol.
